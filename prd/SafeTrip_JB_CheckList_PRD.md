### 1.1 목표
- 전북특별자치도 시군별 축제, 날씨, 공휴일 데이터를 통합한 대시보드형 서비스를 구축한다.

- API Design System PRD의 리소스 구조, 공통 응답 포맷, 에러 체계, 데이터 출처 추적성을 실제 구현 절차에 반영한다.
- Tech Stack PRD의 MVP 권장 스택을 기준으로 개발 순서를 정리하고, 확장 단계 작업을 별도 백로그로 관리한다.

## 7. 5단계: 백엔드 API 구현

### 7.1 공통 API 규칙
- [ ] 모든 엔드포인트는 `/v1` 경로를 사용한다.
- [ ] 리소스명은 복수형 명사, 소문자, 하이픈 구분을 사용한다.
- [ ] 경로 파라미터와 쿼리 파라미터는 `snake_case`를 사용한다.
- [ ] 모든 성공 응답은 `success`, `data`, `meta` Envelope를 따른다.
- [ ] 외부 데이터 포함 응답에는 `source` 객체를 포함한다.
- [ ] 요청 추적을 위해 `X-Request-Id` 또는 서버 생성 `request_id`를 처리한다.

### 7.2 핵심 엔드포인트
- [ ] `GET /v1/regions`를 구현한다.
- [ ] `GET /v1/regions/{region_id}`를 구현한다.
- [ ] `GET /v1/regions/{region_id}/dashboard`를 구현한다.
- [ ] `GET /v1/regions/{region_id}/festivals`를 구현한다.
- [ ] `GET /v1/festivals/{festival_id}`를 구현한다.
- [ ] `GET /v1/festivals/{festival_id}/performance`를 구현한다.
- [ ] `GET /v1/festivals/compare`를 구현한다.
- [ ] `GET /v1/regions/{region_id}/congestion-index`를 구현한다.
- [ ] `GET /v1/regions/{region_id}/saturation`를 구현한다.
- [ ] `GET /v1/regions/{region_id}/ai-insights`를 구현한다.
- [ ] `GET /v1/data-sources`를 구현한다.

### 7.3 검색, 필터링, 페이지네이션
- [ ] 목록 조회에 `limit`, `cursor` 기반 페이지네이션을 적용한다.
- [ ] `sort`, `order` 정렬 파라미터를 지원한다.
- [ ] `start_date`, `end_date` 기간 필터를 지원한다.
- [ ] `region_id` 단일/다중 필터를 지원한다.
- [ ] 잘못된 파라미터는 `INVALID_PARAMETER`로 응답한다.

### 7.4 에러 처리
- [ ] 공통 에러 응답 포맷을 구현한다.
- [ ] `UNAUTHORIZED`, `FORBIDDEN`, `REGION_NOT_FOUND`, `FESTIVAL_NOT_FOUND`를 구현한다.
- [ ] `DATA_NOT_READY`, `RATE_LIMIT_EXCEEDED`, `EXTERNAL_SOURCE_UNAVAILABLE`를 구현한다.
- [ ] `Retry-After` 헤더를 429 응답에 포함한다.
- [ ] Swagger/OpenAPI 문서에 에러 응답 예시를 포함한다.

### 7.5 완료 기준
- [ ] Swagger 문서에서 모든 MVP 엔드포인트를 확인할 수 있다.
- [ ] API Design System PRD의 응답 포맷과 실제 응답이 일치한다.
- [ ] 단위 테스트와 통합 테스트가 핵심 엔드포인트를 검증한다.

## 8. 6단계: 인증, 권한, 보안 구현

### 8.1 인증
- [ ] Public API Key 또는 Public Bearer 토큰 정책을 확정한다.
- [ ] 기관 계정 OAuth 2.0 로그인 흐름을 설계한다.
- [ ] JWT 발급, 갱신, 만료 정책을 구현한다.
- [ ] 내부 관리자 Role을 구현한다.

### 8.2 접근 제어
- [ ] 일반 방문객은 지역 현황, 혼잡 지수, AI 분석 결과 조회만 가능하게 제한한다.
- [ ] 교통기관/경찰은 상세 통계와 과거 축제 비교 데이터를 조회할 수 있게 한다.
- [ ] 축제 운영본부는 담당 축제 성과 리포트와 원시 데이터 export에 접근할 수 있게 한다.
- [ ] 내부 관리자는 전체 CRUD와 데이터 제공기관 연동 관리 권한을 가진다.

### 8.3 API 보호
- [ ] Redis 기반 Rate Limiting을 구현한다.
- [ ] Public API Key는 60 req/min으로 제한한다.
- [ ] 기관 OAuth 계정은 300 req/min으로 제한한다.
- [ ] 관리자 계정은 내부망 기준 정책을 적용한다.
- [ ] API 키와 외부 연동 비밀값은 AWS Secrets Manager 또는 동등한 비밀 관리 도구에 저장한다.

### 8.4 완료 기준
- [ ] 사용자 그룹별 허용/차단 API 테스트가 통과한다.
- [ ] 인증 실패, 권한 부족, 요청 한도 초과 응답이 표준 에러 포맷을 따른다.

## 13. 11단계: 로깅, 모니터링, 알림

### 13.1 로그
- [ ] 모든 API 요청에 `request_id`, 사용자 그룹, 응답 시간, 상태 코드를 기록한다.
- [ ] 외부 API 호출 로그에 provider, status, retry_count를 기록한다.
- [ ] AI 분석 로그에 사용 근거 데이터와 누락 여부를 기록한다.
- [ ] 개인정보 또는 비밀값이 로그에 남지 않도록 마스킹한다.

### 13.2 모니터링

- [ ] Grafana 대시보드에 API, DB, Redis, 배치 작업 상태를 표시한다.
- [ ] `EXTERNAL_SOURCE_UNAVAILABLE` 발생률을 별도 지표로 추적한다.

### 13.3 알림
- [ ] 외부 데이터 제공기관 응답 실패 알림을 Slack Webhook으로 전송한다.

### 13.4 완료 기준
- [ ] 장애 상황을 재현했을 때 로그, 지표, 알림이 모두 생성된다.

## 15. 13단계: QA 및 검수

### 15.1 API 검수
- [ ] OpenAPI 스펙과 실제 응답 필드가 일치한다.
- [ ] 모든 성공 응답이 공통 Envelope를 따른다.
- [ ] 외부 데이터 응답에 `source` 객체가 포함된다.
- [ ] 에러 응답이 표준 포맷을 따른다.
- [ ] Rate Limit, 인증 실패, 권한 부족 테스트가 통과한다.

### 15.2 데이터 검수
- [ ] 방문객 수, 축제 일정, 기상 데이터 매핑이 정확하다.
- [ ] 축제 기간 비교 지표가 기준 기간에 맞게 계산된다.
- [ ] 혼잡 지수와 포화상태가 정의된 기준에 따라 산출된다.
- [ ] fallback 데이터에는 `is_estimated: true`가 적용된다.

### 15.3 프론트엔드 검수
- [ ] 관광객, 교통기관/경찰, 축제 운영본부 화면 분기가 정상 동작한다.
- [ ] 지도와 상태 카드가 실제 API 응답으로 렌더링된다.
- [ ] 로딩, 빈 상태, 에러 상태가 사용자에게 명확히 표시된다.
- [ ] 데이터 출처, 기준일, 갱신일이 화면에서 확인된다.
- [ ] 주요 브라우저와 모바일 화면에서 레이아웃 문제가 없다.

### 15.4 AI 검수
- [ ] AI 요약이 방문객 수, 축제, 날씨 등 실제 근거를 참조한다.
- [ ] 근거 없는 단정 표현을 피한다.
- [ ] Claude API 실패 시 사용자에게 안정적인 fallback 메시지를 보여준다.

### 15.5 완료 기준
- [ ] MVP 출시 전 필수 테스트 케이스가 모두 통과한다.
- [ ] 미해결 이슈가 출시 차단, 출시 후 수정, 확장 단계 항목으로 분류되어 있다.

## 18. MVP 최종 Definition of Done

- [ ] 사용자는 축제 정보, 혼잡 지수, AI 원인 분석을 조회할 수 있다.
- [ ] 교통기관/경찰과 축제 운영본부는 권한에 맞는 상세 데이터에 접근할 수 있다.
- [ ] 모든 핵심 API는 OpenAPI 문서와 일치한다.
- [ ] 모든 외부 데이터 기반 응답은 출처, 기준일, 갱신일, 추정 여부를 제공한다.
- [ ] 외부 API 장애 시 fallback과 운영 알림이 동작한다.
- [ ] 프론트엔드는 실제 API와 연동되어 주요 화면을 안정적으로 렌더링한다.
- [ ] 인증, 권한, Rate Limit, 표준 에러 처리가 구현되어 있다.
- [ ] 스테이징 또는 운영 환경에 Docker 기반으로 배포되어 있다.
- [ ] 로그, 모니터링, 알림으로 장애 원인을 추적할 수 있다.
- [ ] 출시 차단 이슈가 남아 있지 않다.
